# CLAUDE.md

Context for anyone — human or Claude — picking this repo up cold.

## What this repo is

The **user layer** for the fleet: everything that lives in `$HOME`,
deployed with yadm. The **system layer** (packages, services, kernel,
fstab) is the sibling repo
[deployLinux](https://github.com/0n3W4y7ick3t/deployLinux) — keep the
split: if it needs root, it belongs there.

Machines are told apart by **yadm class**, not hostname:
`yadm config local.class desktop` (or `x13` / `wsl` / `server`) and `yadm alt`
materialize the `##class.*` alternates — e.g. the deployed
`~/.config/hypr/machine.lua` is a symlink to `machine.lua##class.desktop`.
Edit the `##class.*` file, never the symlink, and never copy a repo
class-default over it. yadm alt only links *tracked* files: a brand-new
alternate must be `yadm add`ed before alt will materialize its symlink.

## Deployment state (2026-08-13)

yadm is adopted on both machines: neverland (`local.class desktop`) and the
x13 laptop (`local.class x13`, Arch since 2026-08-12), origin = this repo on
each. The one-off-copy era is over: **never `cp` into `$HOME` again**. Commit
here, push, then `yadm pull` on the machine. yadm is a consumer — pull,
`yadm alt` if an alternate changed, done.

**Two machines means the shared files may not assume a distro.** As of
2026-08-13 the shared Hyprland config no longer does: the hyprexpo plugin
(a Gentoo path) and `gentoo-pipewire-launcher` (OpenRC has no user session
to socket-activate pipewire) live in the desktop machine alternate, because
on Arch the plugin line was a hard `hyprctl configerrors` failure that also
killed the `$mod+SHIFT+0` bind. In the Lua config the mod key carries the
same ordering rule: `MOD` is a *global* defined above `require("machine")`,
because require shares globals but not locals — a `local` in hyprland.lua
would be nil inside machine.lua and its binds would never fire.

`machine.lua` is generated by `yadm alt`, which symlinks it to the class
alternate. Nothing tracks a plain `machine.lua`; the fallback is
`machine.lua##default`.

**Hyprland config is Lua since 2026-08-21** (`hyprland.lua` +
`machine.lua##class.*`), migrated ahead of 0.57 which drops hyprlang
support. On 0.56.x the format is chosen at *compositor startup* —
`hyprctl reload` cannot hot-switch formats, and once started on Lua,
`hyprctl eval` works (it refuses on a hyprlang root). The old
`hyprland.conf` + `machine.conf##*` stay tracked as the rollback (delete
`hyprland.lua`, restart, and 0.56.x falls back to them); remove them in a
follow-up commit once 0.57 is deployed and verified on both machines.

**`misc.disable_autoreload = true` is load-bearing, not a preference.** Any
yadm write unlinks that symlink for an instant. Hyprland's config watcher
would fire inside the gap, fail the `require("machine")`, and drop *every*
monitor rule to the generic one — scale and rotation visibly wrong until
something reloads. No hook can win that race:
`post_pull` runs *before* yadm's internal `alt`, so a reload there fires
while the link is still missing. Killing the autoreload removes the race
instead of patching it; reloads are then explicit only ($mod+F5 and the
`.config/yadm/hooks/` hooks, which run `yadm alt` first and reload after).

## How the session starts (neverland)

tty1 login → zsh reads `~/.zprofile` → symlink to `.config/shell/profile`
→ exports the GPU pin (below) → `exec dbus-run-session start-hyprland`.
No display manager anywhere. Logs that survive a failed start:

- `~/.cache/hyprland/session.log` — start-hyprland stdout/stderr, rotated
  to `.old` each login (the profile redirects it; without this a backend
  failure vanishes with the tty scrollback)
- `~/.cache/hyprland/hyprlandCrashReport*.txt` — Hyprland's own reporter
- `$XDG_RUNTIME_DIR/hypr/<sig>/hyprland.log` is tmpfs — gone after reboot

**Window session restore** (2026-08-18): `.scripts/hypr-session` is a
vendored, MIT-licensed copy of hypr-session-restore. **The lua config
manager changes hyprctl itself**: `hyprctl dispatch` evaluates its argument
as lua (`hl.dsp...`), the classic form errors out, and `hyprctl keyword` is
gone ("use eval"); `getoption -j` renamed `.custom` to `.css`. Every script
touching those was re-ported on 2026-08-21 (hypr-session, sysact,
hypr-gaps, hypr-layout, hypr-windows, clippick, clippick-img,
wmenuscreenshots). The first post-migration login proved why: restore's
classic dispatches all failed silently and the 60 s daemon then overwrote
the good snapshot with the empty session — dispatch() now logs failures
instead of swallowing them. `sysact` runs
`hypr-session save` before leave/reboot/shutdown, `exec-once` runs
`hypr-session restore` on login and a `daemon` re-saves every 60 s so a
power-button shutdown is at most a minute stale. Relaunch commands come
from `/proc/<pid>/cmdline`; terminals keep their original flags
(`--class spterm`, `-e bc -lq`) and get their cwd re-injected, so the
class-keyed windowrules and the scratchpads on special workspaces come
back as they were (verified: no `on-created-empty` double-spawn). State is
`~/.local/state/hypr-session/session.json`; `touch
~/.local/state/hypr-session/disabled` skips the next restore.

## Hard-won gotchas

**`AQ_DRM_DEVICES` is a colon-separated list.** The by-path node names
contain colons (`pci-0000:01:00.0-card`), so putting one in that variable
makes aquamarine split it into garbage, find zero GPUs and abort — that
was the 2026-08-12 "Hyprland won't start" (4 identical crash reports).
And `/dev/dri/cardN` is not stable across boots. The pin therefore lives
**only** in `.config/shell/profile`: it resolves the by-path link to the
real `cardN` at login (`uname -n` guard, fail-soft — if the node is
missing the variable stays unset and aquamarine probes every card).
`machine.conf##class.desktop` deliberately does not set it.

**fcitx5 on Wayland**: `XMODIFIERS` only (profile exports it). Forcing
`GTK_IM_MODULE`/`QT_IM_MODULE` breaks the candidate popup — details in
deployLinux CLAUDE.md. Mozc is enabled via `.config/fcitx5/profile`.

## Repo-meta files keep the home root clean

`ls ~` shows no repo files by design (2026-08-14). This file lives at
`.claude/CLAUDE.md` (Claude Code still auto-loads it there). The generated
keybindings doc lives at `.local/share/KEYBINDINGS.md` / `.pdf` —
deliberately NOT `.config/hypr/`, because the keybindings CI triggers on
`.config/hypr/**` and a doc there would re-trigger it on every regen
commit; `$mod+F1` opens the pdf. `README.md` and `LICENSE` are still
tracked at the repo root (GitHub renders/detects them there) but
**sparse-excluded from the worktree** — don't be surprised that they exist
on GitHub yet not in `$HOME`; the `post_pull` hook re-applies the sparse
rule on every machine.

## Committing

**yadm is the commit location on a deployed machine**, not a clone. Edit
the real file in `$HOME`, then `yadm add` / `yadm commit` / `yadm push`.
A `~/akira/rice` checkout, if one exists, is a **reference copy only** —
committing there produces a second history that nothing deploys from.

## What lives in $HOME but is deliberately NOT tracked

`.zshrc` sources `~/.zshrc.local` if it exists, and that file is the seam
for anything machine-local: SDKs installed from tarballs, a version
manager's shell hook. Keep it untracked. Secret env vars go in
`~/.config/shell/profile.local` (chmod 600, gitignored), sourced by the
login profile so the whole graphical session inherits them — `.zshrc.local`
is interactive-shells-only and too late for compositor-launched apps. The same goes for the version
managers themselves (`~/.local/bin/mise`, `~/.local/share/cargo` for
rustup) and their configs — a toolchain pin belongs to one machine and one
project, so tracking it here would only churn the alternates.

The same seam pattern picks GitHub accounts: the tracked `.scripts/gh`
wrapper maps directories to gh accounts through an untracked
`~/.config/gh/dirmap` (tab-separated `<dir prefix>\t<account>`, first match
wins), so `gh auth switch` is never needed. The wrapper only routes gh CLI
commands; git's credential calls follow gh's *active* account (personal),
and directories whose HTTPS remotes belong to the other account pin their
own credential helper inside the untracked gitconfig include chain.
Recreate dirmap and that chain by hand on a new machine.

The bookmarks follow the same seam since 2026-08-17: `.config/shell/bm-dirs`,
`bm-files` and `bm-progs` are gitignored, and `bmd`/`bmf`/`bmp` append to
them freely. The tracked `bm-*.example` files are the seed — `post_pull`
and `bootstrap` copy each one into place when the live file is missing and
run `shortcuts` so the aliases exist. Change defaults in the `.example`,
never expect the live file to be in the repo.

The rule that decides it: **this repo is public, so nothing in it may say
anything about who Leon works for or what he works on.** No employer
names, no account names, no project or repo names, and no directory
bookmarks pointing at work trees — one had slipped into
`.config/shell/bm-dirs` and was removed on 2026-08-13, which is why the
bookmark files stopped being tracked. Personal paths are fine;
`$HOME/akira` is this person's own.
