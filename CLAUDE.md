# CLAUDE.md

Context for anyone — human or Claude — picking this repo up cold.

## What this repo is

The **user layer** for the fleet: everything that lives in `$HOME`,
deployed with yadm. The **system layer** (packages, services, kernel,
fstab) is the sibling repo
[deployLinux](https://github.com/0n3W4y7ick3t/deployLinux) — keep the
split: if it needs root, it belongs there.

Machines are told apart by **yadm class**, not hostname:
`yadm config local.class desktop` (or `x13` / `wsl` / `server`) and `yadm alt`
materialize the `##class.*` alternates — e.g. the deployed
`~/.config/hypr/machine.conf` is a symlink to `machine.conf##class.desktop`.
Edit the `##class.*` file, never the symlink, and never copy the repo's
plain `machine.conf` (the class-default) over it.

## Deployment state (2026-08-13)

yadm is adopted on both machines: neverland (`local.class desktop`) and the
x13 laptop (`local.class x13`, Arch since 2026-08-12), origin = this repo on
each. The one-off-copy era is over: **never `cp` into `$HOME` again**. Commit
here, push, then `yadm pull` on the machine. yadm is a consumer — pull,
`yadm alt` if an alternate changed, done.

**Two machines means the shared files may not assume a distro.** As of
2026-08-13 `hyprland.conf` no longer does: the hyprexpo plugin (a Gentoo
path) and `gentoo-pipewire-launcher` (OpenRC has no user session to
socket-activate pipewire) moved into `machine.conf##class.desktop`, because
on Arch the plugin line was a hard `hyprctl configerrors` failure that also
killed the `$mod+SHIFT+0` bind. `$mod` is therefore defined *above* the
`source =` line now — machine.conf binds keys, and Hyprland substitutes a
`$var` at parse time, so a bind sourced before the definition never fires.

`machine.conf` is generated by `yadm alt`, which symlinks it to the class
alternate. Nothing tracks a plain `machine.conf`; the fallback is
`machine.conf##default`.

**`misc:disable_autoreload = true` is load-bearing, not a preference.** Any
yadm write unlinks that symlink for an instant. Hyprland's config watcher
would fire inside the gap, fail `source=` with "globbing error: found no
match", and drop *every* monitor rule to the generic one — scale and
rotation visibly wrong until something reloads. No hook can win that race:
`post_pull` runs *before* yadm's internal `alt`, so a reload there fires
while the link is still missing. Killing the autoreload removes the race
instead of patching it; reloads are then explicit only ($mod+F5 and the
`.config/yadm/hooks/` hooks, which run `yadm alt` first and reload after).

## How the session starts (neverland)

tty1 login → zsh reads `~/.zprofile` → symlink to `.config/shell/profile`
→ exports the GPU pin (below) → `exec dbus-run-session start-hyprland`.
No display manager anywhere. Logs that survive a failed start:

- `~/.cache/hyprland/session.log` — start-hyprland stdout/stderr, rotated
  to `.old` each login (the profile redirects it; without this a backend
  failure vanishes with the tty scrollback)
- `~/.cache/hyprland/hyprlandCrashReport*.txt` — Hyprland's own reporter
- `$XDG_RUNTIME_DIR/hypr/<sig>/hyprland.log` is tmpfs — gone after reboot

## Hard-won gotchas

**`AQ_DRM_DEVICES` is a colon-separated list.** The by-path node names
contain colons (`pci-0000:01:00.0-card`), so putting one in that variable
makes aquamarine split it into garbage, find zero GPUs and abort — that
was the 2026-08-12 "Hyprland won't start" (4 identical crash reports).
And `/dev/dri/cardN` is not stable across boots. The pin therefore lives
**only** in `.config/shell/profile`: it resolves the by-path link to the
real `cardN` at login (`uname -n` guard, fail-soft — if the node is
missing the variable stays unset and aquamarine probes every card).
`machine.conf##class.desktop` deliberately does not set it.

**fcitx5 on Wayland**: `XMODIFIERS` only (profile exports it). Forcing
`GTK_IM_MODULE`/`QT_IM_MODULE` breaks the candidate popup — details in
deployLinux CLAUDE.md. Mozc is enabled via `.config/fcitx5/profile`.

## Committing

**yadm is the commit location on a deployed machine**, not a clone. Edit
the real file in `$HOME`, then `yadm add` / `yadm commit` / `yadm push`.
A `~/akira/rice` checkout, if one exists, is a **reference copy only** —
committing there produces a second history that nothing deploys from.

## What lives in $HOME but is deliberately NOT tracked

`.zshrc` sources `~/.zshrc.local` if it exists, and that file is the seam
for anything machine-local: SDKs installed from tarballs, a version
manager's shell hook. Keep it untracked. The same goes for the version
managers themselves (`~/.local/bin/mise`, `~/.local/share/cargo` for
rustup) and their configs — a toolchain pin belongs to one machine and one
project, so tracking it here would only churn the alternates.

The rule that decides it: **this repo is public, so nothing in it may say
anything about who Leon works for or what he works on.** No employer
names, no account names, no project or repo names, and no directory
bookmarks pointing at work trees — one had slipped into
`.config/shell/bm-dirs` and was removed on 2026-08-13. Personal paths are
fine; `$HOME/akira` is this person's own.

## Conventions

- Commits: lowercase scoped messages, no `Co-Authored-By` trailer.
  Don't push without asking.
- POSIX-leaning zsh in `.scripts/`; keep scripts self-contained.
